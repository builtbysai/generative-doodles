# №126 · 512 Characters - process notes

## Concept
After Piter Pasma's 512-character SDF constraint pieces. Extreme constraint as art: an animated raymarched landscape is generated by one tiny formula, and the formula itself is the caption. The world occupies the top 80 percent of the frame; below a hairline rule, the actual code renders live in small monospace type with its character count. The world is the proof, the code is the label, and there is nothing else.

## Construction
- Single self-contained page, no libraries. 2D canvas. The generator is a single string of 308 characters (under the 400 aim, well under the 512 cap), held as 8 term segments that join into one arrow function: (x,y,t,s) marching a ray through a two-sine terrain field, 26 steps, distance-scaled stepping, fog and a sine shade term on a hit. The joined string is eval'd once and the resulting function is the only ray function the piece ever calls. The code strip draws the joined string character for character from the same variable, so the displayed code cannot drift from the running code, and the count drawn on the last line is the string's real length followed by /512.
- Rendering: the world is raymarched per cell (6px cells on wide frames, 4px on narrow) and brightness is quantised to 8 levels, each cell filled in bone #E6DFCE with a 1px unfilled row inside the cell, so the shading reads as hatch rows, never as a smooth gradient. Ground #0D0D10, code in dim green #7BA05B only, one colour, no syntax highlighting rainbow.
- Interaction: the world animates on its own, time being one of the formula's inputs. Dragging on the world scrubs the time parameter directly. Dragging on the code strip highlights the term nearest the fingertip, by character position, with a faint glow. Double-tap reseeds the phase s. Never click-to-reload.
- Palette only: ground #0D0D10, world bone #E6DFCE, code #7BA05B with a brighter green reserved for the touched term. Visual Viewport sizing with resize listened to on visualViewport and window; canvas pinned by style width and height in px; phone detection via window.screen with aspect fallback; full-bleed at every size since the composition is the whole frame. A synchronous first frame is drawn at load and requestAnimationFrame is guarded so node-canvas QA works.

## QA log

Desktop frame shows rolling hatched hills with shaded ridge bands under a black sky, horizon near mid height; the strip shows the full formula on two lines ending in the 308/512 count. Mobile wraps the formula to five lines inside the strip with the count intact, terrain full-bleed. The formula was also executed headlessly in node before embedding to verify the terrain, the hit rate and the exact 308 character length. Hans's real-device check is the final gate.
