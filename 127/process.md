# №127 · Summit Circle - process notes

## Concept
From the Berlin summit gathering in the lammetje network study: one canvas, many hands. Twelve simple drawing agents share the frame, each with one signature behaviour and one muted ink, drawing simultaneously and politely steering away from each other's fresh ink. A jam session rather than a composition; the visitor's finger joins as a thirteenth hand.

## Construction
- Single self-contained page, no libraries. 2D canvas. The twelve agents: arcs (ochre), plotter vegetation (sage), ellipses with three discrete weight steps (slate), a hatch-blob hand (bone grey), faint long lines (taupe, low alpha), stipple (dusty copper), contour rings (pale slate), string bands (rust), phase columns (sage grey), membrane dots (deep teal), grid ticks (the single red), glyphs (violet grey). Ground #0D0C0A. No agent uses another's colour, no legend, no names on the canvas.
- Politeness: a coarse occupancy grid (14px cells) tracks fresh marks; each agent probes ahead and to both sides and veers toward the drier side. Heading is a gentle random walk with a clamped turn rate, so paths cruise long distances and mix across the whole frame instead of knotting in place. Marks are stored as stroke records (segments, arcs, ellipses, dots) in a pool capped at 60,000, each fading slowly per frame with the oldest pruned first; the frame is fully redrawn each frame from the pool, which keeps coverage restrained, well under 70 percent.
- Interaction: touch and drag draws in bone white as a thirteenth agent, and the twelve steer away from the finger too. Double-tap clears the canvas for a fresh session. Endless, never click-to-reload.
- Pre-roll: 900 simulation steps run at first layout, so the synchronous first frame already shows a developed, mixed jam rather than twelve isolated starter knots. Visual Viewport sizing with resize listened to on visualViewport and window; canvas pinned by style width and height in px; phone detection via window.screen with aspect fallback; full-bleed composition at every size. A synchronous first frame is drawn at load and requestAnimationFrame is guarded so node-canvas QA works.

## QA log
- Frames rendered from the actual page script (node-canvas) at 1280x900 desktop, 390x844 mobile and 720x720 thumbnail size and inspected before shipping. First pass failed review: a too-strong constant turn rate made every agent circle tightly at its start point, reading as twelve separate doodles on a grid. Fixed by switching to a clamped random-walk heading, raising cruise speed, randomising start positions and lengthening the pre-roll to 900 steps. Second pass shows long stipple and membrane trails arcing across the frame, drifting ring stacks, ellipse trails, hatch swaths and scattered grid ticks all intermixed, with generous dark space kept. Mobile render keeps the same mixture in portrait. Hans's real-device check is the final gate.
