# No.1776 Diverging, Converging (a plan that draws itself) (SV1, PP1023)

Opens EXPANSION #233 stephen-vitiello. Gallery date: 2006 · 11 · 22.
Gallery note: "A red wavefront redraws a dense black circuit-map on paper white; pulses travel the finished paths. Drag to re-route one path."

## Build

Canvas 2D only, no SVG, no WebAudio, no DOM text. Template: live No.1775 index.html, fetched fresh at build.

- Ground: paper white #F4F1EA, full-bleed field on desktop and phones, marginless per the prompt. Ink black #111110, signal red #C8102E for the wavefront, bright red #E0183A for pulses.
- Path graph: 30 orthogonal polylines generated by a seeded RNG (mulberry32, seed 1776). Each path has 4 to 6 right-angle segments with switchback turns and a small square terminal pad at each end. Start points are centre-clustered (65 percent drawn from a squeezed mean of three draws) and the rest spread to the edges, so the network is dense at centre and sparse at the edges.
- Wavefront: the red pen redraws the network path by path at a fixed pen speed of 0.06 normalised field units per second. Total cycle is 309.1 s. Paths already redrawn in the current cycle are full black; the path under the pen is red up to the pen point, with a small red pen dot carrying a slight deterministic jitter (sine and cosine of piece time); paths not yet redrawn this cycle are the previous cycle's ink, faded to 20 percent black, so old paths visibly fade as new ones are laid down.
- Pulses: every finished path carries one pulse, a short bright red segment with a fading tail and a dot, travelling at 0.40 of the path per second with a per-path seeded speed factor (0.7 to 1.3) and offset. Pulse position is a closed-form function of piece time.
- Frame one: fixed phase t = 60 s. The wavefront is on path 6 of 30 at 9.5 percent along it, so six paths are finished black with pulses travelling them and the red pen is mid-network. Verified by probe: wavefront at t = 60 is {idx 6, u 0.095}, at t = 120 it is {idx 11, u 0.948}.
- Drag: pointerdown and pointermove find the nearest path within 26 px and swap in that path's fixed authored alternate polyline (generated from the same seeded stream at build time). The alternate replaces the path geometry for drawing, wavefront and pulses. Frame one is pre-drag, so it stays byte-comparable. Probe verified: reroute(3) marks path 3 rerouted and changes the rendered pixels.
- Plates: black fill with paper-white ink and a thin border, top left with title and date, bottom left with the hint "Drag to re-route one path." Title font shrinks to fit the viewport width, as in the No.1775 template.
- Reduced motion: the animation loop does not start, so the piece rests at the fixed frame one.

## Deviations and interpretations

- No WebAudio: the prompt offers faint clicks as pulses arrive, muted by default. The adaptation flag in the spec says no WebAudio by default, and the visuals carry the piece alone, so no audio code is included. No clicks exist to enable.
- No SVG: the graph is a fixed seeded table drawn on the main canvas, per the adaptation flag.
- The prompt calls the wavefront redrawing "over minutes": the full cycle is about 5 minutes, and any single path takes roughly 5 to 15 seconds to draw.
- The field is full-bleed on desktop as well as phones, following the prompt's "full-bleed drawing field, marginless" composition rather than the usual square-on-desktop layout for field pieces. Documented here as a prompt-driven choice.
- The red wavefront draws the current path in red while it is being laid down; once finished the path turns black, matching the prompt's black network with one signal red for the active wavefront.

## House rules

Visual Viewport sizing with resize listened to on visualViewport and window; canvas pinned in draw() via style.width/height in px; phone detection via window.screen (min dimension under 700 px) with aspect fallback (h > w * 1.15); one synchronous frame at load; requestAnimationFrame guarded with a typeof check; deterministic fixed-phase first frame with seeded RNG only, no Date.now or Math.random anywhere in the script; drag interaction only, never click-to-reload; no AI-signature copy.

## QA

Rendered from the actual script with node ~/workspace/tools/render-piece.js:

- Desktop 1280x900: dense orthogonal black network at centre fading to sparse grey at the edges, terminal pads at path ends, red pen mid-network at top right with red pulse dots and short red dashes on the finished black paths, title plate "Diverging, Converging (a plan that draws itself) / 2006 · 11 · 22" top left fully legible, hint plate bottom left.
- Mobile 390x844: full-bleed network, title plate fits and stays legible, hint plate bottom left, pulses and red pen visible.
- Thumb 720x720: same composition as desktop, plates legible. This render is thumb.png.

Determinism: two independent desktop renders are byte-identical (md5 b2a2442f9b30470a9b793bf499b8ef75). Probe script verified the wavefront advances with piece time and that rerouting path 3 changes the rendered pixels. No fix round was needed: the first renders were inspected and accepted as-is, except for a pre-render fix where the pulse tail was corrected to draw only a short trailing segment instead of painting red from the path origin (caught in code review before the first render, re-rendered after the fix).
