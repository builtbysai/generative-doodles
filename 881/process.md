# No.881 Hairball

Study #108 bnsh_av, PP42 "Connectome" (his March 2026 quantum series: 004 "connectome", 003 "hairball").

## Concept

A living brain slice rendered as a particle network: about a hundred nodes drift inside a slowly rotating tangled ball, edges forming and dissolving as nodes drift in and out of range. The network is a process, not a diagram. Rest dominates: nodes sit dim grey, edges barely there, and firing is the exception. A drag is an electrode: nodes near the finger fire and the firing propagates along edges with per-edge delays, a seizure wave that decays back to quiet over about three seconds. A tap strikes one node; a double-tap silences the whole network for a breath, after which it wakes node by node. Monochrome throughout: brightness is the only channel. The only text is the prompt-specced bottom readout: a FIRING count and a thin rest/activity meter.

## Construction

- Nodes: 100, seeded with mulberry32 (seed 8810042). Each node has a polar home inside the ball (radius distribution biased inward; about 10% are strays placed in the dark penumbra), a slow individual precession, and a small closed-form orbital wobble. Positions are a closed-form function of time; the whole ball rotates at 0.03 rad/s. House viewport rules hold: size from the Visual Viewport API with resize listeners on both visualViewport and window, canvas style pinned in px inside draw(), phone detection via window.screen physical size (min dimension < 700px) with the tall-aspect fallback.
- Edges: rebuilt every frame from current positions with a spatial hash; pairs closer than 0.155 of the frame's short side connect, capped at 650 drawn edges. Edge grey runs #2A2A2A to #8A8A8A and alpha rises with the larger endpoint charge, so an edge brightens while it carries a pulse and fades as the endpoints settle. Nothing about the graph is stored as a picture; it is recomputed from the drift every frame.
- Charge model: each node carries a charge 0..1 decaying with a 0.95 s time constant (visibly back to rest in ~3 s). Charge is frame-integrated state advanced only by a fixed-timestep simulation (DT = 1/60) from the seeded initial state plus recorded stimuli, the house sim pattern. When a node's charge crosses 0.70 upward it fires once (1.1 s refractory) and hands 0.52 of its charge to each current neighbor, delayed by 0.05..0.60 s in proportion to edge length, so cascades travel instead of flashing. Rest is protected two ways: spontaneous firing is a pre-generated seeded schedule only every 2.6..6.4 s, and a single propagated pulse (max 0.52) can never by itself push a resting node over the 0.70 firing threshold; cascades need converging input or a real stimulus.
- Stimuli: drag injects charge into nodes within a radius of the pointer, gentle and narrow for slow drags, wider and hotter as drag speed rises (fast drags make big cascades). Tap injects 1.05 into the nearest node. Double-tap clears all charge, holds a 4 s silence, then wakes nodes on seeded individual delays spread over ~3.6 s.
- Readout: FIRING counts nodes at charge >= 0.58. The threshold sits deliberately above the largest single propagated pulse (0.52), so the counter reads nodes that truly fired rather than the ripple still arriving through them; at frame one it reads exactly 1.
- Audio: lazy WebAudio, created inside the first pointer gesture and typeof-guarded. Rest is a faint 52 Hz thrum at gain 0.016 that fades to zero during a silence. Each firing plays a short soft sine pip, pitch mapped from the node's current degree; voices are capped at 16, stealing the quietest. The QA renderer has no AudioContext and no interaction, so the piece renders and runs completely in silence there.
- Frame one: the simulation owns a seeded past. It is initialized at t = -1.2 and pre-stepped to t = 0 at load, with one recorded stimulus: the innermost node (index 40) fired at t = -0.4. At t = 0 that node sits at charge 0.656, mid-ripple: its nearest neighbors carry 0.44..0.51 and their edges are lit, the rest of the ball is at rest. Frame one is drawn synchronously at load before any animation frame; the loop afterwards is rAF-guarded and anchored to elapsed time since load, never to a wall-clock-derived first frame.

- Rendered with node ~/workspace/tools/render-piece.js at 1280x900 (qa-desktop.png), 390x844 (qa-mobile.png), 720x720 (thumb.png). All render cleanly in silence; the renderer lists only the expected resize and pointer listeners.
- Determinism gate: thumb.png rendered twice and byte-compared with cmp: identical. Second render deleted.
- Read-back, thumb (720x720): dim grey tangled ball centered on black, about ten stray nodes in the penumbra, one bright node just above center with several warming neighbors and brightened edges around it (the seeded ripple), readout "FIRING 1" bottom left, activity meter bottom right with a small fill. Matches the frame-one spec.
- Read-back, desktop (1280x900): same composition at size; ball centered with generous black margin, readout and meter unclipped.
- Read-back, mobile (390x844): phone path taken (scaled-up nodes), ball centered in the tall frame, readout and meter fully visible, nothing clipped.
- Two bugs found and fixed during QA: (1) the pre-step was initialized at simTime 0, so the seeded past never ran and frame one was fully at rest; fixed by initializing the sim clock at t = -1.2. (2) The per-node sleep array defaulted to 0, which silently blocked all deliveries scheduled before t = 0; fixed by initializing it to -1e9. After both fixes a debug harness confirmed seed charge 0.656 and counter semantics at t = 0 before final renders.

## Deviations

- FIRING counter threshold is 0.58 rather than a round 0.5: at 0.5 the still-arriving propagation wave (pulses up to 0.52 that land just before t = 0) counted as firing and frame one read FIRING 4, contradicting the specced frame-one readout of 1. The 0.58 threshold counts only nodes that fired themselves (direct strikes and summed cascades), which is the readout's intent; the ripple remains visible as warming nodes and lit edges.
- Pip pitch uses node degree recomputed from the live edge set each sim step rather than a fixed per-node value, since edges are dynamic; a node's voice rises as its momentary connectivity rises, which tracks the prompt's "pitch by node degree" more literally.
