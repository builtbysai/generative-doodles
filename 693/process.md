# No.693 "Foraging Quipu" — process

EXPANSION #84 ceciliavicuna, prompt block 5 "Foraging Quipu" (verbatim from TASKS.md).

## Concept

Vicuña's Foraging Quipu (IMMA → Whitechapel, 2025–26) gathers what the public finds — seeds, roots, plant matter, textiles, plastics — and weaves it into one suspended quipu. The archive is the work, and it grows the way a foraging archive grows: slowly, one thing at a time, without announcing itself. This piece is that archive as a hanging object. Twelve cords sway in a dark space; found objects dangle from knots along them. Each new day, on first load, one more object is quietly tied on. No counters, no labels, no score: the quipu simply has more on it than it did yesterday. Dragging an object swings and turns it, then it settles back into the sway.

## Construction

Single self-contained `index.html`, canvas 2D, strict eight-color palette (cord #C9B896, seed brown #5C3A21, leaf rust #A85A2E, root tan #C9A96A, petal red #A83232, plastic blue #3E7C8C, feather gray #8A8A86, background #12100D). No text anywhere except the `<title>`.

**Cords.** Twelve cords hang from anchors across the top, lengths 34–64% of the frame height, each a quadratic curve whose control and end points lean with a closed-form pendulum sway (two summed sines, per-cord seeded phase, speed, and amplitude). Sway is a pure function of elapsed time — no integration — so any phase is exact and reproducible. Canvas size comes from the Visual Viewport API with resize listeners on both visualViewport and window; `canvas.style.width/height` are pinned in px inside `draw()`; phone detection uses `window.screen` min dimension < 700px with the aspect fallback.

**Glyphs.** Seven found-object types, all flat glyphic drawings at the knot: seed (ellipse with hilum dot), leaf (pointed oval with vein), root (spiral stroke), wood chip (seeded irregular polygon), petal (folded arc with center crease), plastic fragment (translucent shard at 0.6 alpha), feather (shaft with barbs). Each object carries a seeded variant that jitters its rotation, proportions, and details, and turns slowly as it hangs (rotation is a sine of time plus a term proportional to its drag offset, so a swing visibly turns the object).

**The archive.** Stored in `localStorage` under the key `foraging-quipu-693`. Schema: `{ v: 1, lastDay: <Date#toDateString>, items: [{ t, c, k, s }] }` where `t` = glyph type 0–6, `c` = cord index 0–11, `k` = knot position 0.55–1.0 along the cord, `s` = glyph variant 0–1. Item *n* is not random: it is generated by `mulberry32(693001 + n·7919)`, so the sequence of finds is the same sequence on every machine; the archive records which prefix of it has been tied on. On load: if a stored archive exists and its `lastDay` differs from today and it holds fewer than 60 items, exactly one new object (the next in the seeded sequence) is appended and the archive re-saved. A fresh archive starts with a **base set of five** objects, spread onto distinct cords so a first visit already reads as the beginning of something, per the prompt. Cap: 60 items; a full archive rests.

**Storage guards.** Every `localStorage` access (`getItem`, `setItem`, `JSON.parse`) sits inside `try/catch` with a `typeof localStorage` check first. Absent, denied, or corrupt storage resolves to the fresh in-memory archive; the piece runs identically with storage missing entirely, which is the headless-QA case. Stored items are sanitized on read (type and cord range-checked, knot and variant clamped); an archive with no valid items is treated as absent.

**Interaction.** Pointer (with mouse/touch fallbacks) down near an object grabs it; moving drags its hang offset (clamped to a swing region around its knot); the object's rotation follows the offset. On release a damped spring (stiffness 26, damping 4.2, integrated in the rAF loop) settles it home. There is no other interaction, deliberately: the accumulation is the interaction.

**Determinism, scoped.** Frame one is the synchronous boot draw at sway phase 0 from whatever archive state the environment presents. In QA (no storage), that is always the fresh base set, and two renders byte-match. In a browser, the daily addition resolves once: the first load of a new day appends and saves, so a second load the same day reads back the identical archive and draws the identical frame. Sway is never derived from a wall-clock origin shared across loads; the clock starts at load and frame one is pinned to phase 0. The real date is read only for the once-a-day comparison and is never drawn. The animation clock is anchored at load; `requestAnimationFrame` is typeof-guarded, and the headless renderer (no rAF, no AudioContext, no `document.createElement`, no offscreen canvas, no `ctx.filter`) renders frame one and stops cleanly. An inert `?seed=tNN` QA hook pins the boot phase so later sway phases can be inspected headlessly; it does nothing in normal viewing.

## Deviations

1. **Base set of five on a fresh archive.** The prompt's archive grows one object per day from nothing, which would leave a first-ever frame an empty row of cords. Per the build brief, a fresh archive starts with five objects already tied; growth after that follows the prompt exactly (one per day, cap 60).
2. **Seeded global find sequence.** Which object arrives on a given day is drawn from one fixed seeded sequence indexed by archive length rather than from per-visitor randomness. This keeps the archive contents reproducible and the frame deterministic in any environment that presents the same archive; the foraging fiction is unchanged — the visitor still does not choose what is found.
3. **Drag turns the object directly.** The prompt says a dragged object "turns slowly, showing its glyphic faces"; the glyphs are flat, so the turn is rendered as rotation coupled to the swing rather than a 3D flip.
